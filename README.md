# Twitter 可疑账号检测：监督学习与非监督学习对比

## 项目简介

本项目针对同一数据集和同一问题，分别实现一种非监督学习方法和一种监督学习方法，并对两种机器学习方法进行比较。

项目将使用两种机器学习算法检测“可疑”的 Twitter 用户档案，并从相关维度比较两种算法的结果，之后进一步优化模型。

本仓库包含完成该项目所需的全部资源，包括用于检测可疑 Twitter 用户档案的监督学习和非监督学习方法。

## 代码文件说明

1. `Traitement_des_donnees/`：包含 3 个用于准备数据的文件：
   - `Traitement_des_donnees/1_create.ipynb`：用于将数据导入 MongoDB。
   - `Traitement_des_donnees/2_feature_extaction.ipynb`：用于按用户分组、选择特征，并确定计算分析维度所需的属性。
   - `Traitement_des_donnees/3_features_cacl.ipynb`：用于在 MongoDB 的小型数据集上进行计算，得到项目所需的分析维度。

2. `pca_explorer.ipynb`：用于判断是否需要通过主成分分析（PCA）对数据集降维，以及选择降维后的维度。

3. 机器学习代码分别位于 `SVM/` 和 `K-Means/` 目录中：
   - `SVM/ML_SVM.ipynb`：用于运行 SVM 算法。
   - `SVM/EtiquettesMaker.ipynb`：用于探索标签生成。这只是项目探索过程的一部分；最终标签并非通过该文件中的代码生成，而是使用 K-Means 算法进行标注。

# Suspicious Twitter Account Detection: Comparing Supervised and Unsupervised Learning

## Project Overview

This project implements one unsupervised learning method and one supervised learning method for the same problem using the same dataset, then compares the two machine learning approaches.

The project uses two machine learning algorithms to detect “suspicious” Twitter profiles. Their results are compared across relevant dimensions, followed by further model optimization.

This repository contains all the resources needed for the project, including the supervised and unsupervised learning methods used to detect suspicious Twitter profiles.

## Code and Files

1. `Traitement_des_donnees/` contains three files used to prepare the data:
   - `Traitement_des_donnees/1_create.ipynb`: Imports the data into MongoDB.
   - `Traitement_des_donnees/2_feature_extaction.ipynb`: Groups data by user, selects features, and identifies the attributes used to calculate the analysis dimensions.
   - `Traitement_des_donnees/3_features_cacl.ipynb`: Performs calculations on the small dataset in MongoDB to obtain the project’s analysis dimensions.

2. `pca_explorer.ipynb`: Determines whether the dataset should be reduced using Principal Component Analysis (PCA) and which dimensions to retain.

3. The machine learning code is located in the `SVM/` and `K-Means/` directories:
   - `SVM/ML_SVM.ipynb`: Runs the SVM algorithm.
   - `SVM/EtiquettesMaker.ipynb`: Used to explore label generation. This notebook covers only part of the project’s exploration; the final labels were not generated by its code but were assigned using K-Means.

# Détection de comptes Twitter suspects : comparaison entre apprentissage supervisé et non supervisé

## Présentation du projet

Ce projet met en œuvre une méthode d’apprentissage non supervisé et une méthode d’apprentissage supervisé pour un même problème et sur un même jeu de données, puis compare ces deux approches de machine learning.

Le projet utilise deux algorithmes d’apprentissage automatique pour détecter les profils Twitter « suspects ». Leurs résultats sont comparés selon des dimensions pertinentes, puis les modèles sont optimisés davantage.

Ce dépôt contient toutes les ressources nécessaires au projet, notamment les méthodes d’apprentissage supervisé et non supervisé utilisées pour détecter les profils Twitter suspects.

## Présentation des fichiers de code

1. `Traitement_des_donnees/` contient trois fichiers utilisés pour préparer les données :
   - `Traitement_des_donnees/1_create.ipynb` : importe les données dans MongoDB.
   - `Traitement_des_donnees/2_feature_extaction.ipynb` : regroupe les données par utilisateur, sélectionne les caractéristiques et identifie les attributs utilisés pour calculer les dimensions d’analyse.
   - `Traitement_des_donnees/3_features_cacl.ipynb` : effectue les calculs nécessaires sur le petit jeu de données dans MongoDB afin d’obtenir les dimensions d’analyse du projet.

2. `pca_explorer.ipynb` : permet de déterminer si le jeu de données doit être réduit par analyse en composantes principales (ACP) et combien de dimensions conserver.

3. Le code de machine learning se trouve dans les répertoires `SVM/` et `K-Means/` :
   - `SVM/ML_SVM.ipynb` : exécute l’algorithme SVM.
   - `SVM/EtiquettesMaker.ipynb` : utilisé pour explorer la génération des étiquettes. Ce notebook ne couvre qu’une partie de l’exploration du projet ; les étiquettes finales n’ont pas été générées par son code, mais attribuées à l’aide de K-Means.


   - `K-Means/Kmeans_avec_pca.ipynb` qui est le fichier dans lequel se trouve l'intégralité du code nécessaire pour exécuter notre K-Means avec PCA 


   - `K-Means/Kmeans_sans_pca.ipynb` qui est le fichier dans lequel se trouve l'intégralité du code nécessaire pour exécuter notre K-Means sans PCA
